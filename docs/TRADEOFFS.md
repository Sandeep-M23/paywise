# Trade-offs

Each decision, what it buys, and what it costs.

## Product

| Decision                                                                                               | Why                                                                                                                                                       | Cost / what we'd do next                                                                                                         |
| ------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **Five researched features over many shallow ones** (import, export, history, fairness, raise planner) | Each maps to a sourced HR problem (`RESEARCH.md` §3). Depth over breadth.                                                                                 | No pay ranges/compa-ratio, compression view, or approvals yet. Pay ranges are first in v2.                                       |
| **Salary stays in local currency; no currency conversion**                                             | HR compares pay within a market; exchange rates add a data source and staleness.                                                                          | No single org-wide payroll figure. Data stores currency per row, so dated exchange-rate tables can be added without a migration. |
| **Salary changes are their own action with a reason**, not a field in "edit"                           | Every change is explainable later. That's the audit trail spreadsheets lack.                                                                              | One extra click for HR.                                                                                                          |
| **Deactivate instead of delete**                                                                       | History and past insights stay intact.                                                                                                                    | Data is never truly removed. A retention/erasure policy (GDPR) would need a separate, deliberate flow.                           |
| **Import skips error rows** (after the user has seen them), rather than rejecting the whole file       | One typo in 10,000 rows shouldn't block the other 9,999. The user sees exactly what will be skipped and can download those rows to fix.                   | Partial imports are possible. Mitigated by the preview, the import log, and history entries linked to each import.               |
| **Import matches existing employees by `employee_code`**                                               | Emails change; codes don't.                                                                                                                               | Files must carry the code. Rows without one become errors, not new people.                                                       |
| **Fairness compares full-time employees only**                                                         | Part-time pay reflects hours, which we don't record, so mixing it in made fake gaps.                                                                      | Part-timers aren't analysed. Recording FTE/hours would let us compare hourly pay.                                                |
| **Gender gap: legal 5% flag plus a significance marker**                                               | The 5% rule is the legal trigger, but alone it flagged 95 of about 150 groups on realistic data, mostly noise. Significance tells HR where to look first. | With about 150 groups at 95%, a few "significant" gaps are still chance. The UI says "review", not "proven".                     |
| **Small groups are fully suppressed** (fewer than 5 women or men)                                      | Averages of 2 people effectively reveal their salaries.                                                                                                   | Some teams can't be analysed at all.                                                                                             |
| **Single HR login from environment config**                                                            | One persona; protects confidential data on a public URL.                                                                                                  | No per-user audit ("who changed this"), no roles. Next step: SSO plus a `changed_by` on revisions.                               |

## Engineering

| Decision                                                                        | Why                                                                                                                      | Cost                                                                                                                                                                                                               |
| ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Separate API (Hono) and web (Next.js)** instead of Next route handlers        | Clear layering (routes → services → repositories), testable without Next, the backend stays its own reviewable piece.    | Two deployments.                                                                                                                                                                                                   |
| **Web proxies `/api/*` to the API** (Next rewrites)                             | The session cookie is first-party: no CORS, and no third-party cookie blocking in Safari/Chrome.                         | An extra hop through Vercel's proxy.                                                                                                                                                                               |
| **`packages/shared` for schemas, money, CSV helpers and DTO types**             | Form validation and API validation can't drift; one money module.                                                        | A workspace package to wire up; the API is bundled with esbuild for Vercel because the package ships TypeScript source.                                                                                            |
| **Money as integer minor units (Stripe-style), parsed from strings**            | No float errors; zero- and three-decimal currencies handled by an exponent table.                                        | Formatting must always go through the money module (rule in `CLAUDE.md`).                                                                                                                                          |
| **`salary_amount` denormalised on `employees`**                                 | Fast lists and aggregates.                                                                                               | Two places hold the current salary. Only the revision service and import write it, and always in the same transaction.                                                                                             |
| **PGlite for tests instead of mocks or SQLite**                                 | Real Postgres semantics (`percentile_cont`, `pg_trgm`, `FOR UPDATE`) at in-process speed; no Docker needed to run tests. | PGlite is a WASM build, so behaviour differs from server Postgres in edge cases (e.g. concurrency). Covered by running the same migrations on real Postgres locally.                                               |
| **Infinite, virtualised directory** (batches of 50; only visible rows rendered) | Scanning 10,000 people is natural by scrolling, and the DOM stays at about 40 rows however far you go.                   | No page number to share, so a link restores filters and sort but opens at the top. Offset batches can skip or repeat a row if someone is edited mid-scroll; keyset (cursor) pagination is the fix at larger scale. |
| **⌘K palette and searchable filter comboboxes**                                 | Twenty job titles are faster to type than to scroll; HR can jump to anyone from anywhere.                                | More components to maintain; plain selects remain for short lists (sort, country picker on fairness).                                                                                                              |
| **Directory filters live in the URL; Jotai only for transient UI state**        | Shareable, reloadable views with one source of truth.                                                                    | Slightly more code than a single atom.                                                                                                                                                                             |
| **Next.js `proxy.ts` is only an optimistic redirect**                           | Fast redirect to sign in; the API verifies the signed cookie on every request.                                           | An expired session shows the page shell briefly before the first API call redirects.                                                                                                                               |
| **Statistics in SQL, medians via `percentile_cont`**                            | Matches Excel's `PERCENTILE.INC`, so HR's numbers reconcile.                                                             | Postgres-specific SQL.                                                                                                                                                                                             |
| **No `.xlsx` parsing**                                                          | Excel saves CSV UTF-8 natively; avoids a heavy parser.                                                                   | HR must "Save As CSV" first; the UI says so.                                                                                                                                                                       |
