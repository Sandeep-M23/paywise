# Trade-offs

Each decision, what it buys, and what it costs.

## Product

| Decision                                                                                         | Why                                                                                                                                                                                                                                                       | Cost / what we'd do next                                                                                                                                                            |
| ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Researched features over many shallow ones**, prioritised P0 / P1 / P2                         | Each maps to a sourced HR problem (`RESEARCH.md` §3); P0 is what the assessment needs, P1 differentiates (fairness, raise planner, Ask Paywise).                                                                                                          | No pay ranges/compa-ratio, compression view or approvals yet. Pay ranges are first in v2.                                                                                           |
| **Salary stays in its own currency; no conversion**                                              | HR compares pay within a market; conversion needs a rate source and a policy (which rate, which date).                                                                                                                                                    | No single org-wide payroll figure; every aggregate is per currency, even within one country when overrides exist. Dated rate tables can be added later without a migration.         |
| **Salary changes are their own action with a reason**, not a field in "edit"                     | Every change is explainable later. That's the audit trail spreadsheets lack.                                                                                                                                                                              | One extra click for HR.                                                                                                                                                             |
| **Deactivate instead of delete**                                                                 | History and past insights stay intact.                                                                                                                                                                                                                    | Data is never truly removed. A retention/erasure policy (GDPR) would need a separate, deliberate flow.                                                                              |
| **Import skips error rows** (after the user has seen them), rather than rejecting the whole file | One typo in 10,000 rows shouldn't block the other 9,999. The user sees exactly what will be skipped and can download those rows to fix.                                                                                                                   | Partial imports are possible. Mitigated by the preview, the import log, and history entries linked to each import.                                                                  |
| **Import matches existing employees by `employee_code`**                                         | Emails change; codes don't.                                                                                                                                                                                                                               | Files must carry the code. Rows without one become errors, not new people.                                                                                                          |
| **Fairness compares full-time employees only**                                                   | Part-time pay reflects hours, which we don't record, so mixing it in made fake gaps.                                                                                                                                                                      | Part-timers aren't analysed. Recording FTE/hours would let us compare hourly pay.                                                                                                   |
| **Gender-based differences: a configurable 5% analytical flag plus a confidence marker**         | 5% matches a common reporting convention; alone it flagged 95 of about 150 groups on realistic data, mostly noise. The confidence marker says where to look first. Wording ("potential pay disparity") and a disclaimer avoid reading as a legal finding. | Some flags are still chance; no levelling or tenure adjustment, so the figures are indicators only.                                                                                 |
| **Small groups are fully suppressed** (fewer than 5 women or men)                                | Averages of 2 people effectively reveal their salaries.                                                                                                                                                                                                   | Some teams can't be analysed at all.                                                                                                                                                |
| **Single HR login from environment config, with an authorization seam**                          | One persona; protects confidential data on a public URL. Services already call `authorize(actor, action)`.                                                                                                                                                | The audit log names the shared account, not a person. Next step: SSO and real roles behind the same policy function.                                                                |
| **Future-dated revisions with a cached current salary**, promoted daily                          | Lists, sorting and every aggregate keep reading one table (measured 1–10 ms).                                                                                                                                                                             | The cache can lag a due change by minutes after UTC midnight; closed by cold-start and on-write promotion and an invariant test. Fallback: derive the current salary in each query. |
| **Same-date changes are corrections, not edits**                                                 | History stays append-only and explainable; "the latest-recorded revision for a date wins" is simple to reason about.                                                                                                                                      | A typo fix adds a row instead of replacing one; the UI shows the corrected entry struck through.                                                                                    |
| **Only scheduled revisions can be cancelled**                                                    | A future change hasn't happened yet; cancelling it isn't rewriting history.                                                                                                                                                                               | One mutable field (`cancelled_at`) on an otherwise append-only table; every cancellation is audited.                                                                                |
| **Currency defaults from country, HR can override**                                              | Expat and foreign-currency contracts exist; one rule per row keeps aggregates honest.                                                                                                                                                                     | More validation (supported list, `currency_change` reason), and per-currency rows inside a country.                                                                                 |
| **Import idempotency via a client key + request hash, stored in Postgres**                       | A double click or a retried request can't import twice; no Redis needed.                                                                                                                                                                                  | The key is only as good as the client: a brand-new key for the same file imports again (mitigated by the "already imported" file-hash warning).                                     |
| **Audit written by services in the same transaction** (not database triggers)                    | The actor and intent are known in the service; failures roll back together; easy to test.                                                                                                                                                                 | A raw SQL write outside the services wouldn't be audited; a trigger blocks edits and deletes of audit rows.                                                                         |
| **Ask Paywise is rule-based (no LLM, no generated SQL)**                                         | Predictable, testable, safe over salary data; every answer shows how it was understood.                                                                                                                                                                   | Narrow phrasing coverage; unsupported questions are common at first. An LLM could later produce a `QueryPlan` (validated by the same schema), never SQL.                            |

## Engineering

| Decision                                                                        | Why                                                                                                                                 | Cost                                                                                                                                                                                                               |
| ------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Separate API (Hono) and web (Next.js)** instead of Next route handlers        | Clear layering (routes → controllers → services → repositories), testable without Next, the backend stays its own reviewable piece. | Two deployments.                                                                                                                                                                                                   |
| **Web proxies `/api/*` to the API** (Next rewrites)                             | The session cookie is first-party: no CORS, and no third-party cookie blocking in Safari/Chrome.                                    | An extra hop through Vercel's proxy.                                                                                                                                                                               |
| **`packages/shared` for schemas, money, CSV helpers and DTO types**             | Form validation and API validation can't drift; one money module.                                                                   | A workspace package to wire up; the API is bundled with esbuild for Vercel because the package ships TypeScript source.                                                                                            |
| **Money as integer minor units (Stripe-style), parsed from strings**            | No float errors; zero- and three-decimal currencies handled by an exponent table.                                                   | Formatting must always go through the money module (rule in `CLAUDE.md`).                                                                                                                                          |
| **`salary_amount` denormalised on `employees`**                                 | Fast lists and aggregates.                                                                                                          | Two places hold the current salary. Only the revision service and import write it, and always in the same transaction.                                                                                             |
| **PGlite for tests instead of mocks or SQLite**                                 | Real Postgres semantics (`percentile_cont`, `pg_trgm`, `FOR UPDATE`) at in-process speed; no Docker needed to run tests.            | PGlite is a WASM build, so behaviour differs from server Postgres in edge cases (e.g. concurrency). Covered by running the same migrations on real Postgres locally.                                               |
| **Infinite, virtualised directory** (batches of 50; only visible rows rendered) | Scanning 10,000 people is natural by scrolling, and the DOM stays at about 40 rows however far you go.                              | No page number to share, so a link restores filters and sort but opens at the top. Offset batches can skip or repeat a row if someone is edited mid-scroll; keyset (cursor) pagination is the fix at larger scale. |
| **⌘K palette and searchable filter comboboxes**                                 | Twenty job titles are faster to type than to scroll; HR can jump to anyone from anywhere.                                           | More components to maintain; plain selects remain for short lists (sort, country picker on fairness).                                                                                                              |
| **Directory filters live in the URL; Jotai only for transient UI state**        | Shareable, reloadable views with one source of truth.                                                                               | Slightly more code than a single atom.                                                                                                                                                                             |
| **Next.js `proxy.ts` is only an optimistic redirect**                           | Fast redirect to sign in; the API verifies the signed cookie on every request.                                                      | An expired session shows the page shell briefly before the first API call redirects.                                                                                                                               |
| **Statistics in SQL, medians via `percentile_cont`**                            | Matches Excel's `PERCENTILE.INC`, so HR's numbers reconcile.                                                                        | Postgres-specific SQL.                                                                                                                                                                                             |
| **No `.xlsx` parsing**                                                          | Excel saves CSV UTF-8 natively; avoids a heavy parser.                                                                              | HR must "Save As CSV" first; the UI says so.                                                                                                                                                                       |
| **Two Vercel projects (web proxies `/api/*`) instead of one**                   | The API deploys, tests and scales on its own; Next stays a UI app; one origin for the browser either way.                           | Two deploys and environment sets, and a proxy hop of a few ms. Switching to one project later is a configuration change.                                                                                           |
| **Login rate limit in Postgres**                                                | Serverless instances share no memory; no new infrastructure.                                                                        | A write per failed login; distributed attacks from many IPs need platform firewall rules.                                                                                                                          |
| **Bulk writes lock employees in id order**                                      | Two raise plans or imports touching the same people can't deadlock.                                                                 | Large plans hold locks on many rows for the length of one transaction (under a second at 10k).                                                                                                                     |
